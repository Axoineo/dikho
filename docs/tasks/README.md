# Task Briefs

Use a task brief for work that spans sessions, agents, substantial design
choices or a risky rollout.

1. Copy `_template.md` to `YYYY-MM-DD-short-name.md`.
2. Keep facts, decisions, completed work and remaining work current.
3. Do not put secrets, production data, full logs or chat transcripts here.
4. Link relevant ADRs and issues rather than copying them.
5. When complete, move durable decisions to `docs/decisions/`.
6. Delete the brief when it has no continuing historical value, or mark it
   complete and move it to an archive only if the record is useful.

Task briefs are coordination state, not permanent system truth. Product,
architecture, invariant and deployment documents take precedence.
