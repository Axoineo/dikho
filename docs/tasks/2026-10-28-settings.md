# Task: Settings that make Dikho configurable (phase 1)

Status: active (migration applied 2026-10-28; dashboard in review)
Owner: Dikho Global Media LLP (owner) with a coding agent
Started: 2026-10-28
Last updated: 2026-10-28

## Goal

A real Settings area in place of the current page (theme plus a privacy
note): personal settings for everyone, organization settings for Owners and
Admins, in one consistent layout.

## Why now

The owner asked for settings that make the CRM customizable for each person,
plus useful general ones, researched against leading CRMs (HubSpot, Zoho,
Pipedrive, Zoho Books for India). Several values the business changes are
fixed in code today (dropdown values, media), and the company profile used
on invoices has no edit screen.

## Decisions made (owner, 2026-10-28)

- Organization settings are changed by Owners and Admins through a new
  `settings.manage` permission (Admin role gets it; Owners hold everything).
- Order numbers will be automatic but editable (phase 2).
- Build phase 1 first.

## Phase 1 scope

- Layout: left list grouped "Your account" / "Organization", one page per
  section at `/settings/<section>`, cards with label/hint left and control
  right. Personal changes save on click; organization pages use Save/Cancel.
- Your account: Profile (read-only), Preferences (theme, table density,
  start page, rows per page), Sign-in and security (sessions).
- Organization: Company (issuer profile and bank details in
  `organization_profiles`), Regional (date format, number style), Lists and
  media (dropdown values; media and sub media).

## Later phases (not in this task)

- Phase 2: numbering (automatic, editable SO/PO numbers; invoice series;
  financial-year start), sales and tax defaults, security policy (idle and
  maximum session), modules on/off.
- Phase 3: notifications (needs a notification system), integrations status,
  data export.

## Design

- Migration `supabase/migrations/20261028120000_settings.sql`, additive:
  `settings.manage`; `staff_members.preferences` + `set_my_preferences()`;
  `my_access()` also returns `preferences`; `organization_settings` (one
  row); `option_lists` (seeded with today's code values); `hidden` on
  `media` / `sub_media`; functions for reading and saving, each checking
  `is_staff()` and, for organization changes, `settings.manage`; every
  organization change goes to `audit_log`. New tables: RLS on, direct
  privileges revoked, the restrictive "staff members only" policy.
- The dashboard keeps working before the migration is applied: missing
  functions or columns fall back to today's built-in values.

## Rollout

1. Owner approves the migration; apply it (it is additive).
2. Deploy the dashboard.
Rollback: the dashboard falls back by itself; the migration's objects can
stay (nothing depends on them).

## Work completed (2026-10-28, uncommitted on `ux/apple-audit-fixes`)

- Migration and SQL tests (`supabase/tests/settings.sql`).
- `src/lib/settings.js`: one store for organization settings, dropdown
  values and preferences, with the built-in fallback; `src/lib/format.js`
  display formatters follow Regional.
- `src/features/settings/`: the new layout and six pages. Breakpoints are
  container queries on the Settings area, so a tablet with the sidebar open
  gets the phone layout instead of a squeezed one.
- Wired into the screens: order type/status, purchase status, item type,
  courier status and row colour dropdowns on sales and purchase orders;
  registration on client and vendor forms; hidden media left out of the
  vendor form (except a vendor's current one) and vendor registration; rows
  per page on Clients, Vendors and both order lists; compact density on the
  four CRM tables; start page at sign-in; WhatsApp overview counts.
- Preview harness: `scripts/preview/crm.html?page=/settings/<section>` with
  an in-memory stand-in for the settings functions (`&db=old` answers as
  before the migration, `&role=viewer` lacks `settings.manage`).
